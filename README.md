# 飞书 Agent 卡片

AstrBot 飞书回复展示插件。收到 Agent 请求后立即创建卡片，在同一张卡更新处理状态、正文、工具摘要、来源和真实模型用量。

当前为 **0.2.1 服务器验收版**，仅验证 AstrBot **4.28.0** 的 `lark` 官方适配器。尚未发布 GitHub 或插件市场；`repo` 元数据将在独立仓库确定后填写。

## 安装与启停

公开发布后，在 AstrBot 插件管理中选择通过 GitHub 仓库地址安装。插件目录必须以本目录为仓库根目录，包含 `main.py`、`metadata.yaml`、`_conf_schema.json`。

当前预览由项目的插件专用预发布入口安装到服务器；用户可在 AstrBot 插件管理中找到「飞书 Agent 卡片」，修改配置、重载或禁用。无需新建飞书应用、填写第二套密钥、安装系统服务或修改 AstrBot 源码。

插件复用已配置飞书客户端，需要当前应用具备 CardKit 创建/更新卡片及回复消息的权限。开通权限后仍须按照飞书应用流程发布生效。创建卡片失败时保留原生回复；运行中更新失败时继续消费模型输出，在收尾阶段重试并补发普通正文。

## 展示与行为

- 即时卡片在 AstrBot 已决定进入 LLM 的等待钩子创建，普通未唤醒群消息不触发。
- 处理过程：宿主真实生命周期、工具开始/返回、请求重试及模型切换。没有额外模型调用，不展示原始 reasoning。
- 正文：同卡定时更新（默认 1.5 秒），工具阶段保留当前卡片。超过约 10 KB 正文后续页；不截断最终内容。代码围栏跨页会补齐显示边界；极长表格建议使用原生 table 组件分页。
- 工具：显示名称、耗时、返回/失败状态，不输出参数、原始结果或供应商错误正文。
- 来源：成功工具名称显示为「工具结果」；只有明确来源合同才展示文档链接，不把随意出现的 URL 当成引用。
- 用量：只累计每个模型请求的非 chunk 终态用量，含缓存输入；失败或缺失用量会标明统计不完整。未返回的费用/Token 不推算。
- 费用：可选管理员维护价格。未设置时不显示费用；展示的是按已返回用量估算，不是供应商账单。
- 失败/取消：明确终态。插件停用会关闭自身卡片并恢复原有发送方式。
- 重启：仅保存未完成卡片 ID、平台 ID、序号和时间；启动后尝试将遗留卡片标为中断，不自动重放原请求。原文、业务结果、密钥不落入插件数据。

**会话规则保持 AstrBot 原有设置。** 本版不实现普通引用消息新建/恢复会话、运行中追加指令或卡片停止按钮，不会写出尚未实现的交互提示。普通附件仍由原生适配器发送。

## 配置

插件后台支持总开关、实例 ID 列表、私聊/群聊开关、过程/工具/来源/用量可见性、过程默认折叠、更新间隔和模型价格。

价格 JSON 以卡片实际展示的 `供应商标识/模型` 为键。每个模型提供每百万 Token 的 `input`、`cached_input`、`output` 三项单价。币种由 `price_currency` 指定；不做汇率换算。价格缺失或格式无效时隐藏费用。

## 来源扩展合同

其他插件可向当前 `event` 登记实际取回、允许在当前会话展示的来源：

```python
event.set_extra("feishu_card_sources", [
    {"title": "文档标题", "url": "https://example.com/doc", "type": "知识库"}
])
```

MCP 工具结果的 `structuredContent.sources` 支持同样结构。本插件不改变工具授权，也不声称所有知识库实现均已自动适配。来源最多 20 项，按标题/链接/类型去重。HTTPS URL 不允许凭据、查询参数、fragment、本地地址或明显令牌路径；无法安全展示时只保留标题。调用方负责来源真实性和当前用户权限。

## 兼容实现

公开钩子负责等待、请求、Agent 生命周期及工具事件；每个事件实例独立绑定发送方法。仅为读取逐请求用量/重试/最终错误，临时包装 v4.28.0 的两个模型迭代方法。包装器继续调用原实现，不改模型选择、重试次数、业务推理或工具调用。方法恢复有所有权检查；不兼容版本停用扩展并保留原生回复。

不要同时启用其他接管飞书流式发送的插件；与其他插件的组合兼容需要单独验证。当前模型重试策略完全沿用宿主，本插件显示等待，不改变上游可用性。

## 验证

纯渲染测试可在普通 Python 环境以 `python -B -m unittest discover -s tests -p test_card.py` 运行。完整测试需要 AstrBot 4.28.0 环境：`python -B -m unittest discover -s tests -v`。测试使用明确标记的测试事件和模拟传输，仅验证机制，不代表真实业务验收。

服务器验收另执行真实飞书 CardKit 创建/更新/终态结构检查，但不向任何用户投递测试消息。最终视觉与业务交付由用户通过当前飞书机器人验收。

## 0.2.1 展示层次

正式回答为独立正文区，以分隔线、加粗标题和正常字号突出；辅助过程、工具和来源采用浅灰折叠面板与明确箭头。模型用量、耗时和底部提示使用灰色小字。工具边界前的模型公开说明归入处理过程，宿主工具状态不进入正文；最终正文以宿主最终回答为准，不使用关键词识别业务内容。

卡片不重复引用原问题，保留飞书原生回复引用。正文标题优先使用模型在最终回答开头生成的主题标题，并以标题字号展示；无标题时以截短的问题文本兜底。不额外调用模型，用户明确要求的输出格式优先。旧版 show_question 配置不再生效。

展示顺序：主题标题、正式回答、分隔线、处理过程、工具调用、知识与数据来源、模型用量及提示。


## Agent 原生组件工具（0.2.1）

- `feishu_card_guide`：按场景查询原生组件与代码、表格、图表、图片、多栏、按钮、表单示例。
- `feishu_card_render`：接收完整 **JSON 2.0** 文档及完整文字兜底，先创建未发送的卡片校验结构，再更新当前回复。原生 header、body、组件及嵌套字段保留；辅助过程、来源、用量仍在底部。模型最终的“已生成卡片”不会覆盖内容。
- `feishu_card_upload_image`：将当前任务已生成的 PNG/JPEG/GIF/WebP 上传成真实 img_key；默认仅允许 data/temp 和 data/plugin_data，管理员可配置 image_roots。文件限 10 MB，不下载远程 URL。

组件入口不按 tag 白名单限制，飞书新增的合法 JSON 2.0 组件可直接使用；这不代表所有组件、客户端或组合均已逐项验收。卡片字节数、组件数量、应用权限和客户端能力仍由飞书决定。当前文档限 24 KB，复杂内容应拆分为可切换的视图，不能静默裁剪业务数据。JSON 1.0 与搭建平台模板不是本工具的输入格式，需要先转换或解析为 JSON 2.0；音视频和文件附件仍由 AstrBot 原生消息能力发送。

### 交互继续处理

飞书应用后台：**事件与回调 → 回调配置 → 使用长连接接收回调 → 添加“卡片回传交互（card.action.trigger）”**，按后台要求保存并发布应用。只订阅“接收消息”不够。

为原生组件填写 `behaviors: [{"type": "callback", "value": {"action": "希望继续处理的任务"}}]`。表单提交按钮还需 `form_action_type: "submit"`。插件自动绑定当前用户与会话；提交的表单、选择值会作为用户输入进入同一个 Agent 会话，并发送新的回复卡片，保留原卡片内容。不执行任意回调 URL，也不把输入当作系统指令。

仅允许原对话发起人在原聊天操作；Agent 忙碌时提示等待，同一视图只接受一次操作，避免重复启动后续任务。链接跳转行为仍由飞书处理。绑定仅在内存保存，24 小时过期；插件重载或重启后旧交互需重新生成。当前支持 AstrBot 4.28.0 **socket** 适配器；webhook 模式或已有其他插件占用回调处理器时拒绝生成回调型卡片，避免静默失效。

验收建议：要求 Agent 展示一段 Python 代码、用表格和柱状图展示测试数据、再生成一个补充需求表单；提交后检查是否沿用原会话发送新卡片，且原卡片内容不变。需启用本插件工具（如 Agent 使用工具白名单，应加入上面三个名称）。插件不自动发送验收消息。
